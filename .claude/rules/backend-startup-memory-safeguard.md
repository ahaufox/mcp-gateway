# 启动与内存防范规则 (Startup & Memory Safeguard)

## 1. 异步启动死锁防范
- **禁止在模块级别执行阻塞操作**: 严禁在模块导入阶段执行耗时的初始化建立连接、第三方服务检测或繁重的本地序列化操作。
- **后台任务隔离**: 任何耗时或可能阻塞的后台任务在启动时，必须包装在后台异步任务中，不得阻塞主线程的启动，确保 API 接口或服务的心跳尽快响应。

## 2. 内存与 GPU 防范
- **分步加载策略**: 当需要并发运行或集成多种大型模型服务时，不要在启动阶段并发加载。必须控制先后顺序以避免短时间内系统内存或显存尖峰（Spike）导致 OOM (Out Of Memory)。
- **配置隔离与平稳降级**: 关键资源（如本地模型缓存、可选连接配置）必须可通过配置文件控制开启/关闭。如果环境受限，系统必须能够平稳降级至轻量模式，而不是直接崩溃。
- **进程资源清理**: 任何处理长连接、多进程或子进程任务的代码，在遇到异常退出时必须具备 `finally` 块或清理机制显式释放外部进程和内存资源。

## 3. 网络与代理兼容性
- 代码在初始化阶段若涉及代理配置清理或动态消除代理环境变量，必须注意与系统 Logger 的初始化时序，防止时序冲突导致丢失启动日志。

## 4. 相关技能 (Related Skills)
执行本规则前，应加载以下技能：
- **`infra-env-diagnostics`**：环境诊断与 SRE 排障。出现服务启动挂起、OOM、依赖冲突、端口占用时，可以调用该技能进行系统级根因分析。
