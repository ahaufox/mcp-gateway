# 每日开发进度逆向生成 (Daily Progress Sync)

## 何时使用

- 每日/每周需要向项目管理或需求方同步真实的开发进度。
- 历史开发记录过于简略或丢失，需要从真实代码库还原工作量与业务影响。
- 自动化撰写或扩充项目版本发布日志。

## 执行步骤

### Step 1: 提取指定日期的代码变更明细

使用 Git 获取目标日期的 `git log --stat` 及 Commit Message 历史，必要时对关键 Commit 使用 `git show` 读取代码 Diff。

### Step 2: 代码与业务逻辑映射分析

分析涉及的文件路径、类名、变量名变更，执行：

1. 聚类与分类（后端架构、前端交互、UI设计、ASR 核心、数据库等）
1. 提炼功能点（将代码变更提炼为直白的功能点）
1. 推演实际业务影响（包含核心代码文件名，阐述对系统或用户的实际价值）

### Step 3: 格式化表格生成

将聚合后的分析结果转化为标准 Markdown 表格：
`| 类别 | 功能点 / 事项 | 详细描述 (业务价值与实现细节) | 状态 |`

### Step 4: 注入目标进度文档

定位到目标进度文档对应日期区域，插入或替换生成的表格内容（按时间倒序排列）。

## 核心规则

- **代码即事实**：所有功能点必须在 Git 变更记录中有物理文件依据。
- **表头锁定**：表格列名为系统保留常量，禁止精简或重命名。
- **技术商业融合**：体现技术的硬核（文件名/架构变更）与业务的温度（提效/防漏/风控）。

## 输入参数

| 参数名 | 类型 | 默认值 | 描述 |
| :--- | :--- | :--- | :--- |
| `target_date` | `string` | 今天 | 目标日期，格式 YYYY-MM-DD |
| `doc_path` | `string` | `沟通记录/开发进度-飞箭.md` | 目标进度文档路径 |

## 输出示例

```json
{
  "status": "success",
  "message": "进度同步完成",
  "data": {
    "date": "2026-06-08",
    "entries": [],
    "inserted_at": "沟通记录/开发进度-飞箭.md"
  }
}
