# 全栈通用核心准则

## 1. 架构演进与风险分级
在任何全栈决策中，遵循：**安全 > 质量 > 速度**。
- **决策理念**：决策快、其次稳、最后优。
- **P0 (阻断级)**: 密钥/PII 泄露、SQL 注入、鉴权绕过、数据不可逆丢失、危险命令。
- **P1 (必验级)**: 登录/鉴权逻辑、核心业务流程、外部 API 集成、数据库迁移。
- **P2 (建议级)**: UI/文案微调、内部工具、监控指标。

## 2. 核心红线
- **安全**: 严禁明文存储敏感信息（密钥、Token）。严禁字符串拼接构造 SQL。严禁暴露未鉴权的敏感接口。
- **质量**: 严禁重构与逻辑变更混合提交。严禁硬编码环境变量。核心逻辑必须捕获异常并有追踪点。
- **数据库**: 数据库结构变更必须使用标准迁移机制，严禁直接在生产库执行 DDL。
- **测试与调试**: 严禁硬编码测试或调试凭证。对于测试与调试辅助变量，必须从环境变量（env）中读取，用于 API 请求、测试、调试等环节。

## 3. 语言规范
- **强制中文回复**: 无论用户用何种语言，Agent 必须始终用中文回复、编写文档、注释及 **Git 提交信息**。
- **禁止中英混合标题**: 所有标题必须是纯中文，不使用英文括号备注与英文缩写标题。
- **术语处理**: 必要英文术语请放入正文句子中说明，不进入标题层级。

## 4. 文件路径与操作规范
- **禁止绝对路径**: 严禁在内部文档或链接中使用绝对路径。必须始终使用相对路径。
- **Git 提交**: 提交信息必须使用语义化前缀（如 `feat:`, `fix:`, `docs:`）且必须为中文。详见 `general-git-commit-message.md`。
- **一次性脚本管理**: 涉及临时设计/原型调试的一次性脚本，**严禁放置于项目根目录**。必须保存至 `tmp/` 目录下，使用后应及时清理。

## 5. 项目状态前置阅读要求
- **核心事实来源**: `docs/` 目录是项目当前状态的核心事实来源。不要只凭局部代码或旧记忆判断当前项目状态。
- **强制触发场景**: 凡涉及功能实现、方案设计、文档编写、任务拆解、问题修复、计划输出，开始前必须先从 `docs/` 读取当前上下文。
- **默认阅读顺序**:
  1. `docs/ROADMAP_CN.md`
  1. `docs/FUTURE_ITERATION_PLAN.md`
  1. `docs/DEVELOPMENT_CN.md`
- **冲突处理**: 若用户即时指令、局部上下文与文档现有内容冲突，必须先指出冲突，再说明本次采用的依据，不得忽略文档中的当前状态直接展开编写。

## 6. 接口与数据规范
- **RESTful**: 优先使用 `/api` 前缀。路径必须遵循资源导向原则，**路径中严禁包含任何动词**（如禁止 `/get_user`），必须使用复数名词表示资源（如 `/users`）。
- **响应一致性**: 保持 JSON 结构稳定。
- **数据清洗收敛**: 后端数据清洗必须在解析/转换层统一完成，禁止在各渲染组件中做 ad-hoc 修复。

## 7. 全链路字段映射防呆 (Cross-Stack Field Mapping Safeguard)
AI 代码生成的字段映射 Bug 根源在于**上下文漂移**：当后端的 `snake_case` 与 TS/React 前端的 `camelCase` 并存，且数据在各层之间传递时需要手动重新声明类型，AI 极易在生成样板代码时搞混字段。核心解决方案是将转换逻辑收敛到框架底层，并在业务逻辑层实行绝对的"强类型独治"。

### 7.1 核心原则
- **消除中间状态**：转换逻辑由框架全局自动完成，禁止在业务层手动写 `snake_case ↔ camelCase` 转换。
- **强类型独治**：前端禁止手写 API 响应 interface，必须从自动生成的 API 契约导入。
- **单一事实来源**：后端 API 规范是唯一的契约源。

### 7.2 分层职责
- 后端 Model/Schema：自动处理 alias，保持对外暴露的 API 属性均为 camelCase 格式。
- API 契约：自动生成 OpenAPI (JSON/YAML) 规范。
- 前端类型生成：通过工具根据后端规范自动生成前端数据契约定义。
- 前端状态/组件：直接引用生成的类型，避免手动编写 interface 引起映射错误。
